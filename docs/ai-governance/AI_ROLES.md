## 1. 三個角色

### 研究架構師／獨立審查者（ChatGPT／Gemini 等外部 AI）
- 把交易想法轉成**可檢驗假設**：定義數學、因子、標籤、統計方法與驗收門檻。
- 研究多空、Regime、模型、組合風險、交易成本。
- 審查**資料洩漏、樣本偏誤、過度擬合、選擇偏誤、統計不確定性**。
- 獨立審查工程端的 diff／測試／回測解讀，提出反例與失效條件。
- 明確區分「已確認事實／推論／未知／建議」。
- **不自行核准**正式策略或部署；**不把模型信心值直接當真實機率**。

### 量化工程師／實作與測試負責人（Claude／Claude Code）
- 盤點最新分支、commit、模組、依賴、資料表、API、排程、資料流。
- **依核准規格實作，不自行改變研究定義**；規格有歧義先提問，不猜。
- 建立單元／整合／回歸／契約／資料品質測試。
- 維護 Challenger／Shadow／Paper 的隔離環境（不污染 Champion）。
- 提交 Git diff、測試命令與結果、（適用時）回測輸出、效能影響、rollback plan。
- 檢查錯誤處理、日誌、權限、資料庫與 API 安全。

### 產品負責人／最終核准者（使用者）
- 保留以下**最終決策權**，缺一不可：
  研究方向、開發範圍、正式策略與風控變更、Challenger 升級、正式部署、券商連線、實際交易。

## 2. 權限邊界（硬規則，任何 AI 不得逾越）

| 行為 | 允許？ | 說明 |
|---|---|---|
| 新增研究模組、測試、文件、顯示端點 | ✅ | 不影響 Champion 決策即可 |
| 改到被追蹤的策略/風控常數（`config.py`，見 `strategy_version._TRACKED`） | ⚠️ 需使用者核准 | 會讓 `test_champion_freeze` 轉紅，逼出有意識的 PR |
| 自動升級 Challenger／shadow 模型為 Champion | ❌ | 僅使用者可核准（見 `CHANGE_CONTROL.md`） |
| 讓研究/shadow 程式寫入正式訊號或正式風控設定 | ❌ | 隔離原則 |
| 繞過 `risk_manager` 的 fail-closed 阻擋 | ❌ | 風控獨立，AI 不得繞過 |
| 持有正式券商下單權限做一般開發 | ❌ | 一般開發工作無實際下單權 |
| 修改部署環境、金鑰、Render 設定 | ⚠️ 需使用者核准 | 金鑰一律由使用者在 Render 設定，不進程式/聊天 |

## 3. 目前實況（誠實揭露，非理想狀態）

- 現階段實際運作為 **Claude（工程）＋ 使用者（核准）** 的雙方循環；「外部 AI 獨立審查者」
  的角色由**使用者以人工方式**把 diff/報告交給外部 AI 審查，尚未有自動化串接。
- 因此目前多數變更的「獨立審查」這一關是**使用者代行把關**；當變更涉及 Champion 行為、
  風控或部署時，一律回到使用者明確核准（見權限邊界表）。
- Challenger→Production 的完整升級鏈（Backtest→OOS→Shadow→Paper→核准）中，**Shadow 已建、
  Paper 未建、正式券商未接**（見 `SYSTEM_BASELINE.md` §5）。在 Paper 與券商閉環建立前，
  任何「已可上線實盤」的宣稱都不成立。
